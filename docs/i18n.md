# Vietnamese / English

The application uses next-intl with App Router and Next.js 16 `proxy.ts`.
Vietnamese URLs stay unchanged (`/`, `/booths`, `/booths/admin/login`).
English pages use `/en` (`/en`, `/en/booths`, `/en/booths/admin/login`).
Page and layout files are under `app/[locale]`; shared components and styles stay
in their original folders. API endpoints and public asset URLs have no locale prefix.
The current checkout contains no game routes. When restoring them, put their route
files under `app/[locale]/game` and use the same translation/navigation helpers.

## Content

- `messages/vi.json` and `messages/en.json`: UI copy, validation and error messages.
- `messages/source-keys.json`: Vietnamese source text to stable message ID registry.
  Existing IDs must not be renumbered: API responses also use them as `error_code`.
- `useCopy()` from `i18n/copy.ts` translates authored copy and interpolates `{v0}`,
  `{v1}`, etc. Both dictionaries must use identical placeholders.
- `useLocalizedData()` is only for authored, immutable editorial data (programs,
  schedules, guests). Never use it on database records or submitted descriptions.
- Use the locale-aware `Link`, `useRouter` and `usePathname` from
  `i18n/navigation.ts` for internal page navigation. Keep `/api/...` requests and
  asset paths unchanged.

To add a message, choose a new descriptive ID, add the Vietnamese source to the
registry and add both translations. In a Client Component:

```tsx
const t = useCopy();
return <button>{t("Nội dung tiếng Việt")}</button>;
```

Brand names, booth IDs, account details, transfer references, voucher codes and
submitted text remain unchanged. Category option values also stay unchanged;
only their displayed labels are translated. No Supabase migration is required.
Server errors retain `error` for backward compatibility and add `error_code`;
clients translate the code with `useCopy()`.

## Switching and drafts

VI / EN preserves the current path, query and anchor and navigates without a full
page reload. Locale detection is disabled so shared unprefixed links consistently
open Vietnamese. The URL determines the active language.

An in-memory bridge keeps the guest booking fields, selected location, files and
submission key across language switches. It does not persist private details to
localStorage or cookies. It is not a draft recovery system for browser reloads.
Language switching is ignored while that booking form is submitting. Open modal
dialogs keep the header inert until closed.

Dates and numbers follow the locale; admin timestamps use `Asia/Ho_Chi_Minh`.
Metadata has localized descriptions, canonical URLs, hreflang and Open Graph locales.
Social image handlers read `params.locale` directly, since `next/root-params`
is unavailable inside Route Handlers. English footer group labels use live text
and the existing logos; Vietnamese keeps the original footer artwork.
Hero title artwork already uses English and is shared by both locales.

## Verification

```sh
node --test scripts/i18n.test.mjs
pnpm build
pnpm test:e2e tests/i18n.spec.ts
```

Browser tests mock proposal/admin data and do not submit or approve real applications.
